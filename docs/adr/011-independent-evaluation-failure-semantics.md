# ADR 011 — Independent evaluation that exposes failure

Date: October 15, 2026. Status: implemented and locally executed.

CHAOSLAB's extractive judge checks the JSON contract independently of ATLAS validation helpers. Citation identity alone was insufficient: a valid capability citation could be attached to the wrong requirement, an adapter could mark its output approved, and an empty trace could pass an aggregate retry comparison. The judge now checks requirement-to-RFP binding, evidence-only-from-knowledge scope, initial pending review/version, exact extractive draft composition, consistent evidence status, and complete finite nonnegative stage/attempt metadata. Mutation tests demonstrate each boundary. Trace checks validate self-reported metadata; they are not independent forensic measurement of every retrieval call. This scorer is specifically for the extractive contract, not a semantic faithfulness judge for arbitrary LLM prose.

Each adapter invocation now runs in a fresh process with JSON input copies, a configurable wall deadline (default ten seconds, maximum 120), 1.5 MB input and 2 MB output budgets. The child uses POSIX file-size limits; the parent terminates its own process group on timeout/completion and discards private stderr. Adapter exceptions become bounded type-only failure records. Adapters are trusted code with the user's filesystem/network permissions; this is not a hostile-code sandbox or a validated Windows implementation. Child startup, serialization and judging now contribute to reported end-to-end latency. Earlier in-process timings are not directly comparable.

Every timing repetition must pass for an authored case to pass. Quality counts use its first repetition and repetitions do not increase sample size. Inconsistent pass/fail repeats are separately reported. Failed/unknown invocation cost remains unknown rather than zero. Source hashes are frozen before execution and source/dataset changes prevent report publication. Existing known failures remain regression fixtures.

The six adversarial probes were authored before running them. Their actual result is three passed and three failed: paraphrased review hijacking and zero-width instructions contaminate evidence; benign discussion of system prompts is wrongly omitted. All citation-integrity checks passed, showing that provenance does not imply trustworthy content. The baseline has no tool execution and these probes do not measure exfiltration or live LLM injection resistance. Do not improve the headline by relabeling failures or piling new phrases into a blacklist. Future model integration must retain untrusted-data boundaries, constrained capabilities and human decision ownership; semantic selection must be evaluated against separate held-out labels.
