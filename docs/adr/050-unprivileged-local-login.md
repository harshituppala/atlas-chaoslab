# Admit one unprivileged loopback login origin

Real provider acceptance initially tried the approved port-443 loopback callback. The operating system refused the listener for the unprivileged process. Running the application as an administrator would give it unnecessary filesystem and process access, so development gets one explicit alternative: `https://127.0.0.1:8443`.

Only the local callback/resource pair can use that exception. The callback must end in `/auth/callback`, the resource must be `/api`, and both must use the same literal `127.0.0.1:8443` origin. The general URL validator and all provider/issuer/key pins retain their standard-port policy. DNS names, other ports/addresses and mismatched origins remain refused. Existing Host, Origin, secure-cookie and PKCE checks are unchanged and still include the configured port.

Twelve new controls passed, including private settings admission, refusal of lookalike origins and rejection of the wrong Host or Origin at the start route. The native suite passed 784 tests, with eighteen optional database groups skipped. Actual local TLS requests using the generated certificate passed health and auth discovery and rejected an anonymous session and the port-443 Origin. These are separate from browser/provider authentication.

The owner created the Cognito identity, explicitly approved its local reviewer role, and approved registering the additional callback. The local grant was applied with a transactional audit entry, and Cognito displayed a successful app-client update with both callbacks registered. No IAM role, cloud policy, paid-model permission or public service was added by those changes. Private identity and configuration records remain under ignored `var/`.

The in-app browser rejected the self-signed certificate. The owner handled Safari’s warning; no automated warning bypass or OS trust-store change was made. The first real authorization request then exposed a separate [resource/scope mismatch](051-cognito-resource-scope-binding.md). After that correction, Safari reaches Cognito’s password step. Replacing the temporary password is the owner’s step, and the authenticated callback and workspace flow remain unverified. The service is private local SQLite, not durable hosted storage. Operator details are in the [managed-login guide](../managed-login-development.md#private-loopback-without-administrator-privileges).
