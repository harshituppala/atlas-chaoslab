# ADR 040: consume login attempts before exchanging codes

Date: October 21, 2026. Status: backend component implemented and checked offline. No login routes are enabled.

The API already verifies resource-bound access JWTs, but a browser cannot yet obtain one through the application. Add the authorization-code exchange as a separate component before introducing callback routes and session cookies. It uses the explicit Cognito trust profile, an operator-pinned provider origin and one exact HTTPS callback URL. It is not wired into the private workbench or public fictional lab.

Each attempt has an independent random state, browser binding and PKCE verifier. Only a digest of the binding is retained alongside the verifier. Pending attempts expire after five minutes, with a bounded registry. A callback must present the matching state and browser binding. The attempt is consumed before contacting the token endpoint, so concurrent callbacks and ambiguous provider failures cannot replay the exchange. Two token exchanges may run at once; a capacity refusal makes no provider call and leaves its waiting attempt usable.

The authorization request selects code flow, S256, the required API scopes and the resource audience. The backend sends the code verifier only to the pinned token endpoint, follows no redirects and ignores proxy environment variables. Response bytes and connection/read times are bounded; elapsed time is checked between chunks. Compressed responses are rejected. These controls do not establish a strict end-to-end deadline across DNS, key fetching and arbitrary transport behavior.

An accepted response still passes through the existing signature, issuer, audience, client, scope and access-purpose verifier. ID tokens cannot substitute for access tokens. Refresh tokens and provider claims about application roles are not returned. Results use the earlier expiry of the signed token and the response lifetime. Failures expose one fixed message and no provider body, code, verifier or token. Sensitive result and attempt objects have no field-printing representation.

Thirty-nine focused cases passed using controlled HTTP and real RSA-signed synthetic JWTs. They cover PKCE binding, wrong browsers, replay, expiry, admission, slow streams, redirects, malformed/oversized payloads and claim mismatches. The full native suite passed 537 tests, with eighteen optional PostgreSQL groups skipped. The first mock responses were already consumed; correcting them to unread streams exercised the intended transport path. A later concurrency-test syntax error was corrected before the passing run. The [offline report](../../reports/login-exchange-offline.json) binds source, tests and actual JUnit files.

A caller must still set and validate an HttpOnly binding cookie, remove callback queries from logs, create application sessions, resolve workspace membership and implement browser logout/expiry. Pending state is process-local; restarts invalidate it. Provider-domain ownership, actual app-client settings and real browser/provider login require separate acceptance. No AWS resource or user was created, no provider request was made and no hosted login claim follows. ATLAS analysis semantics and pipeline versions are unchanged.

Protocol references checked October 21: [Cognito authorization endpoint](https://docs.aws.amazon.com/cognito/latest/developerguide/authorization-endpoint.html), [token endpoint](https://docs.aws.amazon.com/cognito/latest/developerguide/token-endpoint.html), [PKCE](https://docs.aws.amazon.com/cognito/latest/developerguide/using-pkce-in-authorization-code.html).
