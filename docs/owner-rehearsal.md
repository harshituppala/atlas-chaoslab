# Explain and defend the work

This is a rehearsal checklist. It does not certify the owner's understanding or record a completed interview. Use the [recording checklist](recording-checklist.md) for the two short demonstrations. Close private tabs and connect to the local workspace off camera.

## First pass: tell the story

Explain ATLAS in one sentence using the four-hour requirement and eight-hour promise. Upload the fictional documents, inspect the source, save a reasoned decision and find its audit entry. Explain why a matching quote does not establish that the requirement is met.

Then explain CHAOSLAB in one sentence. Run a correct saved comparison and a wrong answer, broken citation and missing attempt. Explain the difference between exit 1 (quality failure with a report) and exit 2 (invalid experiment, previous report retained). Show one external-test limitation alongside its headline result.

## Unscripted questions

- What prevents an old worker from publishing after another worker takes ownership?
- What happens if two reviewers save different decisions at once?
- Which state survives a local restart, and which public-lab state is temporary?
- What is separately verified about real Cognito, PostgreSQL transport and the hosted sample?
- Why is the evaluator independently installable if the projects share a repository?
- Why can 77.5% correct labels coexist with 49.4% correct labels plus complete evidence?
- What is still unknown about user usefulness and generalization?

Point to the relevant code or report before answering. If unsure, say so and inspect it. The goal is understanding, not memorizing a claim.

## Small live exercise

On a disposable local branch or copy, add a fictional saved-answer failure case or change an expected threshold in a new development fixture. Predict the result before running it, inspect the report, and explain the failure. Do not edit frozen datasets, historical expectations, provider records or paid cohorts. Revert the exercise afterward or retain it separately as a new development example.

## Completion record

Keep a private dated note identifying which tasks were demonstrated unaided, which required help, and what to revisit. Recordings and actual owner observation are still pending until performed. A browser automation clip may show software behavior; it cannot establish the owner's narration, reasoning or independent implementation ability.
